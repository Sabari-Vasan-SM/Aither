# ⚡ BitBeam — File Sharing Through Light, Not Servers

> **Zero Cloud. Zero WebSockets. Zero WebRTC. 100% Optical Photon Transfer.**

BitBeam is a privacy-first, zero-storage optical file-sharing web application. It converts files into an animated sequence of high-density QR code frames on a sender screen, which are captured by a receiver device's camera, verified with CRC-32 and SHA-256 cryptographic checksums, and reconstructed byte-for-byte in local browser memory.

---

## 🌟 Key Features

- **True Air-Gap Capability**: Transfer files between two physically separate devices (e.g. laptop to phone) with Wi-Fi and Cellular radios completely turned off.
- **Zero Server File Ingress**: No backend endpoints, no S3 buckets, no cloud file retention, no WebSockets, no WebRTC signaling servers.
- **Robust Multi-Frame Protocol (BB1)**:
  - 32-bit CRC protection on every chunk frame for instantaneous corruption rejection.
  - Interleaved metadata frames containing filename, MIME type, chunk count, and SHA-256.
  - Complete out-of-order frame assembly & automatic deduplication.
  - Selective retransmission requests (generate a reverse QR to loop only missing frames).
- **Modern Developer UI**:
  - High-contrast, clean SaaS interface with dark/cyber styling.
  - Fullscreen QR mode for maximum camera resolution capture.
  - Real-time chunk defragmentation matrix visualizer (watch chunks get filled live).
  - Telemetry counters: FPS, duplicate frames, missing frames, and estimated duration.
  - Direct in-browser preview for images, audio, and documents.
- **Offline Progressive Web App (PWA)**:
  - Workbox service worker precaches all application assets for offline use.
- **Single-Device Loopback Lab**:
  - Built-in simulation workbench for testing file transfers, stress-testing simulated packet loss, and verifying bit-for-bit reconstruction on a single machine.

## 📜 BitBeam Protocol Specification (BB1)

Every optical frame starts with the protocol prefix `BB1` and uses pipe-delimited compact fields.

### 1. Metadata Frame (`M`)
Transmitted as Frame 0 and periodically interleaved every 12 frames:
```text
BB1|M|{sessionId}|{totalChunks}|{fileSize}|{sha256}|{mimeType}|{b64FileName}
```
- `sessionId`: 8-character unique alphanumeric transfer session ID.
- `totalChunks`: Total number of binary chunks.
- `fileSize`: File length in bytes.
- `sha256`: 64-character lowercase hexadecimal SHA-256 checksum.
- `mimeType`: Original file MIME type (e.g. `image/png`).
- `b64FileName`: UTF-8 safe Base64 encoded original filename.

### 2. Data Chunk Frame (`D`)
Contains the chunk payload with sequence index and CRC-32:
```text
BB1|D|{sessionId}|{chunkIndex}|{totalChunks}|{crc32}|{b64Payload}
```
- `chunkIndex`: 0-indexed integer (0 to `totalChunks` - 1).
- `totalChunks`: Included in every data frame for rapid synchronization.
- `crc32`: 8-character hex CRC-32 checksum of the decoded binary chunk.
- `b64Payload`: Binary-safe Base64 representation of the slice.

### 3. Retransmission Request Frame (`R`)
Generated by the receiver to command the sender to transmit only missing chunks:
```text
BB1|R|{sessionId}|{missingIndicesCommaSeparated}
```

## ⚡ Optical Throughput & Performance

Optical transfer speeds depend on camera capture frame rate and screen resolution:

| Chunk Size | Frame Rate (FPS) | Effective Throughput | 100 KB File Time | 1 MB File Time |
| :--- | :--- | :--- | :--- | :--- |
| **256 Bytes** | 8 FPS | ~2.0 KB/s | ~50 seconds | ~8.3 minutes |
| **384 Bytes** *(Recommended)* | 10 FPS | ~3.8 KB/s | ~26 seconds | ~4.3 minutes |
| **512 Bytes** | 15 FPS | ~7.6 KB/s | ~13 seconds | ~2.1 minutes |

> **Recommended Usage**: Ideal for confidential documents, passwords, seed phrases, keys, tickets, configurations, and photos up to ~5 MB. For larger archives, high screen brightness and steady camera alignment are advised.

## 🚀 Getting Started

### 1. Prerequisites
- Node.js `v18+` or `v20+` / `v22+`
- npm `v9+` or `v10+`

### 2. Installation
```bash
npm install
```

### 3. Run Development Server
```bash
npm run dev
```
Open [http://localhost:5173](http://localhost:5173) in your browser.

### 4. Run Automated Protocol Tests
```bash
npm test
```
Runs the Vitest suite testing:
- Empty file handling (0 bytes)
- Binary buffers and Unicode filenames
- Out-of-order and duplicate frame resilience
- Corrupted frame detection & CRC-32 rejection
- SHA-256 mismatch rejection
- Retransmission request generation

### 5. Production Build
```bash
npm run build
```
Generates production bundles and Service Worker in `dist/`.

## 🔒 Privacy & Verification Audit

To independently confirm zero-storage operation:
1. Open Chrome DevTools (`F12`) and select the **Network** tab.
2. Check the **Disable cache** option and clear the network log.
3. Select a file and transmit it over optical QR.
4. **Result**: `0` HTTP/WebSocket/WebRTC requests are initiated.
